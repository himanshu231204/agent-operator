# Phase 8 — Production Hardening: Detailed Implementation Plan

**Branch**: `phase-8-production`

## Goal

Harden the operator for production deployment with structured retries, background worker processing, enhanced observability, deployment documentation, and a complete CLI.

## Architecture / proposed approach

1. **Structured retries**: Wrap tool calls and LLM calls with `tenacity` retry decorators. Retry on `RateLimitError`, `ModelError`, `ToolError` (all retryable). Do NOT retry `AuthenticationError`, `ValidationError`, `ApprovalRequiredError`.

2. **Background worker**: Implement `app/workers/task_worker.py` with `asyncio.Task` per run. Worker polls PostgreSQL `tasks` table (`SELECT ... FOR UPDATE SKIP LOCKED`) for tasks in `CREATED` or `WAITING_FOR_APPROVAL` (after approval) state, then drives the orchestrator. Expose `start_worker()` / `stop_worker()` lifecycle.

3. **LangSmith tracing**: Extend `OperatorCallbackHandler` to upload traces when `LANGCHAIN_TRACING_V2=true` and `LANGCHAIN_API_KEY` are set. Use `langsmith.Client` for trace upload. Graceful no-op when not configured.

4. **CLI expansion**: Add `run`, `status`, `logs` commands to existing `cli.py`. `run` creates a task and streams status. `status` shows task state. `logs` fetches recent agent runs for a task.

5. **Deployment docs**: Add `docs/deployment.md` covering Docker Compose, environment variables, scaling the worker, and monitoring.

6. **Skills packaging**: Add `skills/packager.py` that validates all SKILL.md contracts and exports a JSON manifest.

```python
from tenacity import (
    retry,
    stop_after_attempt,
    wait_exponential,
    retry_if_exception_type,
    RetryCallState,
)

_RETRYABLE_ERRORS = (RateLimitError, ModelError, ToolError)

def _make_retry(fn):
    return retry(
        stop=stop_after_attempt(3),
        wait=wait_exponential(multiplier=1, min=1, max=10),
        retry=retry_if_exception_type(_RETRYABLE_ERRORS),
        before_sleep=lambda retry_state: logger.warning(
            "tool.retry",
            tool_name=retry_state.kwargs.get("tool_name"),
            attempt=retry_state.attempt_number,
        ),
    )(fn)
```

## Risks, tradeoffs, and open questions

1. **Retry safety**: Retries are only applied to idempotent tool calls. Tools like `social_publish_x` check idempotency before calling the API, so retries are safe. However, if a tool has side effects without idempotency checks, retries could cause duplicates. Document this constraint.

2. **Worker scaling**: `SELECT ... FOR UPDATE SKIP LOCKED` allows multiple worker instances to coordinate via PostgreSQL. However, each worker needs its own LiteLLM provider connections. Monitor connection pool exhaustion.

3. **LangSmith cost**: Trace upload adds latency and cost. Make it opt-in via env vars (already planned). Consider batching trace uploads in future.

4. **CLI transport**: The CLI uses HTTP to the running API. For local development this is fine. For remote deployments, the CLI would need auth tokens. Out of scope for Phase 8.

5. **Skills packaging**: The packager validates SKILL.md structure but doesn't enforce semantic correctness. Future work could validate that referenced tools actually exist in the registry.
